# 有限温度相図の作成

既知の0 K安定構造から各候補相の自由エネルギーを評価し、相平衡を求める。初期の計算にはMLIPを用いる。ユーザーが選んだ方法を優先し、全固相にMDやSQSを一律に要求しない。

## 入力と計算範囲

- 元素系、圧力、温度・組成範囲、既知構造とエネルギー、使用可能なMLIP・計算環境を確認する。既存情報から分かる項目は再質問しない。
- 既知の0 K安定相だけでは高温の候補相は網羅できない。液相、固溶体、必要な準安定結晶を候補に加え、候補を限定した場合は結果にも明記する。
- 0 Kのエネルギー凸包、有限温度の平衡相図、準安定相図を区別する。
- 調査、計算設計、実行、描画のどこまでが依頼かを判断する。スキルの使用だけで長時間計算や環境の変更まで依頼されたとみなさない。

## 方法の選択

| 対象 | 初期方針 |
|---|---|
| 完全規則・固定組成の結晶 | 規則構造のスーパーセル。SQS不要。phonon/QHAまたはcalphyでG(T) |
| 不規則固溶体 | 組成別SQSまたは複数のランダム配置。配置エントロピーを別途整合 |
| 組成幅を持つ規則相 | 副格子・反サイト・空孔を定義し、組成別の自由エネルギーを評価 |
| 液相 | MLIP＋MD＋熱力学積分、または対象系の既存CALPHAD液相モデル |

- 通常のphonon/QHAは安定結晶の振動に使う。液体スナップショットのphononを液相自由エネルギーとみなさない。
- calphyはLAMMPSを使う自由エネルギー計算ツール。pyironは任意のジョブ・データ管理基盤であり必須ではない。
- calphyの二元相図機能を使う場合は、導入版における固定組成相・限定組成範囲相の扱いを確認する。多元系への対応を二元系から推測しない。
- 具体的な計算には [詳細ワークフロー](references/workflow.md) を読む。API・GPU対応・QHA設定は [資料と実例](references/sources.md) の公式資料と導入版で確認する。
- calphy・pycalphad・pyironの既存例がどの工程に対応し、何が欠けているかは [実行済みの例と工程の対応](references/examples.md) を読む。実行済みの入力・結果はプロジェクトの `calphy-examples/`、`pycalphad-examples/`、`pyiron-examples/` にあり、まとめは `docs/examples.html`。
- 例に無い工程（01、SQS・副格子、phonon/QHA 本線、CE+MC、TDB 化、誤差感度）を公開コードで補う候補と、導入済み calphy の `PhaseDiagram` クラスの範囲は [公開ソースの調査](references/public-sources.md) を読む。
- それらを実装したプロジェクトのパッケージ `ftphase/`（環境 `env/ftphase`）の使い方と検証結果は [ftphase パッケージ](references/ftphase.md) を読む。新しい系の計算はこのパッケージの表（FreeEnergyTable）に揃えてから凸包を取る。 calphy を GPU（`gpu=True`、`env/lammps-gpu/bin/lmp_gpu`）で回すときの注意点：GPU 1 枚ではジョブが直列になるため、総スループットは CPU 8 コアと同程度です。利点は 1 本の待ち時間短縮と、CPU を QHA に空けられることです。

## 熱力学上の必須事項

- 全相でエネルギー基準、圧力、組成の定義、単位を揃える。eV/atomとJ/mol-atoms、化学式単位と原子単位を混同しない。
- 固溶幅はG(T,x)の競合から決まる安定組成範囲。緩和後に構造が保たれる範囲、入力した組成範囲、SQS生成可能範囲ではない。
- 配置エントロピーは配置数の統計に由来する。SQS一つや通常の固相MDだけから自動的には得られない。
- 理想混合は完全ランダム配置の近似。規則相では副格子ごとの占有率とサイト数を使う。短範囲秩序や欠陥平衡が重要ならMC・クラスター展開等を検討する。
- MCスワップを実行しただけで絶対配置自由エネルギーを得たとしない。参照状態と積分経路を定義する。
- 振動・配置・理想混合の寄与を二重計上しない。calphyのMD自由エネルギーにphonon free energyをそのまま加えない。
- 固相QHAと古典液相MDを組み合わせる場合は、零点振動・核量子効果の扱いを明示する。
- MLIPの絶対エネルギーを既存TDBに直接継ぎ足さない。共通参照状態への変換と純元素・既知境界での検証を行う。

## 別の計算機への移行・再開

- このプロジェクトの移行先はALAMODE・MLIP導入済み。既存環境を調べて利用し、AiiDA/MCPやcalphy/LAMMPSまで導入済みとは仮定しない。
- どの MLIP がどのバイナリ・経路（calphy CPU/GPU、QHA、`fix atom/swap`、共存 MD、CE+MC）で使えるか、補間関数を使わない経路の計算量は [使える MLIP](references/mlip.md) を読む（長い版 `docs/mlip.html`）。
- 移行・再開時は [移行先での確認と検証順](references/migration.md) を読む。プロジェクトの `docs/migration.html` に転送例と引き継ぎ文、`docs/obsolete_workflow.html` に最新の式と説明がある。
- 実行パス・モデル・スケジューラを確認し、小規模接続検証の後に計算を拡大する。文書の数値例と移行先の実測結果を区別する。

## 出力

計算方法・近似、候補相、構造生成条件、MLIPとソフトウェアの版、自由エネルギーと誤差、参照状態、相図、再現手順を残す。未実行の手順と実測結果を分ける。自由エネルギーのフィット誤差が相境界に与える影響も確認する。
