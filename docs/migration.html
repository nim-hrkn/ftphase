別の大規模計算機への移行・計算再開

更新日：2026-10-21。相図計算workflow ／ 実行済みの例と工程の対応 ／ phase-diagramスキル

移行先にはALAMODEとMLIPが導入済みです。既存環境を利用し、利用方法・モデル・計算資源を確認してから小規模検証へ進みます。本資料は移行の手順書であり、転送・接続・ジョブ投入はまだ行っていません。相図計算の完成済みプログラムや実計算済み相図を引き継ぐものではありません。

2. 転送例

以下はLinux/WSLでの例です。元のプロジェクト直下で実行します。USER、HOST、TRANSFER_DIRは利用する接続先に置き換えます。現在の文書・スキル・資料を固める例であり、別の場所にあるモデルや計算データは含みません。

# 元の計算機：プロジェクト直下
 tar -czf ../phasediagram-handoff.tar.gz CLAUDE.md docs skills 資料
 sha256sum ../phasediagram-handoff.tar.gz > ../phasediagram-handoff.tar.gz.sha256
 scp ../phasediagram-handoff.tar.gz ../phasediagram-handoff.tar.gz.sha256 USER@HOST:TRANSFER_DIR/

展開先には空の専用ディレクトリを使います。既存の計算結果と混ぜず、Windows側の絶対パスは移行先のパスに置き換えます。Python/Conda環境や実行バイナリはコピーせず、導入済み環境を有効化します。

# 移行先：転送先のディレクトリ内
 sha256sum -c phasediagram-handoff.tar.gz.sha256
 mkdir phasediagram-handoff
 tar -xzf phasediagram-handoff.tar.gz -C phasediagram-handoff
 cd phasediagram-handoff

docs/obsolete_workflow.htmlを開き、SVG・ローカルPDF・スキルへのリンクを確認します。計算ノードにブラウザは必須ではなく、文書は手元でも参照できます。移行先のエージェントにはプロジェクト直下を作業ディレクトリとして、CLAUDE.mdとskills/phase-diagram/SKILL.mdを明示的に読ませます。スキルの自動検出は移行先の設定に依存します。

3. 導入済み環境で確認する事項

項目記録・確認する内容
ALAMODE実行ファイルのパス・版、起動方法、MPI/OpenMP対応、必要な環境有効化。力データ入力と結果の単位を確認する。
MLIPモデル名・版・重みのパスとSHA-256、対応元素、精度設定、Python/APIまたはLAMMPS等の呼び出し方。導入済みというだけでは対象系での精度やTI対応は確定しない。
計算資源スケジューラの種類、キュー、アカウント、CPU/GPU種類、メモリ、制限時間、MPIランクとスレッド数、scratchと保存先。施設の既存ジョブ例を使う。
実行環境module/Conda等の有効化手順、Pythonと依存ライブラリ、GPUドライバ・ランタイム。ログインノードで重い計算を実行せず、施設の運用に従う。
追加ツール選んだ経路に必要なものだけ確認する。SQSにはicet/mcsqs等、CE＋MCには相応の計算環境、液相TIにはcalphy＋MLIP対応LAMMPS、CALPHAD経路にはTDBと平衡計算ソフト。
AiiDA・MCPALAMODEの導入とは別に、aiida-alamode、AiiDAプロファイル・DB・ストレージ・daemon、computer/code設定、MCP接続を確認する。元のプロファイル名やPK、絶対パスをそのまま使わない。

AiiDA/MCPがない場合も、ALAMODEとMLIPを直接呼び出す経路で計算を設計できます。AiiDAの計算履歴を引き継ぐ場合は、対象データのアーカイブexport/import等を導入版で確認します。プロジェクトフォルダの転送だけではAiiDAのDB・履歴は移りません。既存のラッパースクリプトも、入門資料に記載があるだけで移行先に存在するとは仮定しません。

ホスト情報が未確定のため、具体的なsbatch/qsub、MPIランチャー、GPU指定、ALAMODE・MLIPの実行コマンドはここでは固定しません。移行先で動く既存例をもとに、環境有効化と投入コマンドを保存してから本計算へ進みます。

4. 小規模検証から本計算へ

  1. 入力条件を確定：対象元素系、構造、組成、温度・圧力範囲、MLIPモデル、必要な相を一覧にする。本資料のAl–Li等の数値例を実際の計算対象と決めつけない。
  2. MLIP単点評価：小さな既知構造でエネルギー・力・応力を計算する。元の計算結果があれば同じ構造・モデル・精度で照合し、なければ新しい基準結果として保存する。元素順序と単位を確認する。
  3. 固相の最小経路：一つの構造・体積で変位生成→MLIP力評価→ALAMODE力定数フィット→phononを通す。単一体積の動作確認をQHA完成としない。虚振動・音響モード・スーパーセル等を確認後、体積系列へ広げる。
  4. 採用経路の追加確認：SQS/CE＋MCを使うなら組成・配置・周期・乱数と結果保存を確認する。液相TIを使うなら通常MDだけでなく、λ=0、0.5、1でスケーリングされたエネルギー・力・ビリアルを確認し、小規模TIを実行する。LAMMPSへのMLIP接続がなければその経路は未準備として扱う。
  5. 規模を拡大：構造・組成・体積・変位・温度・反復の独立計算をジョブ配列等に分配する。CPU/GPU当たりの性能とメモリを小規模測定し、MPIとスレッドの過剰割当を避ける。
  6. 統合：原子数規格化、電子・配置・振動の寄与、元素参照を統一し、相平衡へ渡す。配置寄与の二重計上と不適切な相の外挿を確認する。

5. 再現・再開のための記録

各ジョブについて入力・構造・モデルハッシュ、コードと環境の版、実行コマンド、ジョブスクリプト、ジョブID、乱数、出力、終了状態を残します。結果はphase、composition、T、P、G、uncertainty、volume、method、reference_state、配置項の有無を記録します。入力と中間データをscratchだけに残さず、完了結果を永続領域へ保存します。未実行・実行中・成功・失敗を分け、再開時に未完了の仕事を特定できるようにします。
