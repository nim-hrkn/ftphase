2. 補間関数を使わない経路（B 系）での可否と計算量

「補間関数を使わない」こと自体は MLIP を選ばない。差が出るのは、手法が pair style に課す条件（fix sgcmc だけ EAM 専用の高速経路）と、MC の試行ごとに全エネルギーを計算する分の計算量である。

手法使える MLIP条件・計算量
半大正準 MC（fix atom/swap + MD）すべて試行ごとに全系のエネルギーを前後 2 回計算（fix atom/swap の文書）。コストは「試行数 × 全エネルギー 1 回」。EAM の Ag–Cu（2,048 原子、Δμ 36 点 × 3 温度、各点 20 + 20 ps）は 8 ランクで 25 分/等温線。ACE・GRACE-FS は 1 回のエネルギーが EAM の 50〜100 倍重く、GPU で 2,048 原子 0.05 s/回（grace/fs/kk の実測 2.6 s / 50 ステップ）として同じ試行数なら 1 点 1〜2 時間、1 系 100〜200 GPU 時間。試行数と Δμ 点数を絞れば日単位。GPU + pace/kk の組合せは未検証。
分散拘束 SGC（fix sgcmc、VCSGC、Sadigh 2012）高速な実装は EAM のみ（eam/alloy、eam/fs）LAMMPS の文書どおり、他の pair style では「全エネルギー再計算・直列 1 プロセス」の汎用経路に落ちるので実質不可。VCSGC が要るなら CE 上の mchammer（ftphase.ce.vcsgc_scan）で代替。
二相共存 MD（界面法）すべて、GPU 可通常の MD だけ。EAM の例（agcu_sgcmc/coexist.py、6,144 原子 × 400 ps）を ACE で GPU なら 1 本 15〜20 時間、2,048 原子なら数時間。融点・液相線向き。
Gibbs–Duhem 積分すべて共存する 2 相の MD から ΔH・Δx を取って dμ/dT = −ΔS/Δx を積分。自作が要る。
CE + MC（icet、SGC / VCSGC、ftphase.ce）学習エネルギーの計算に ASE で呼べるものすべて（LAMMPSlib 経由の上記全部、MatterSim・SevenNet、tensorpotential）MC は CE 上で走るので MLIP の重さは学習だけ（Ag–Cu の 631 構造で 3 分）。CE の打ち切り誤差（Ag–Cu で 9 meV/atom）と振動項の欠落が残る（docs/ftphase.html 3.9）。
calphy TI + 離散凸包（A-1、関数なし）第 1 節の全部、GPU は ACE・GRACE・SNAP現行経路（05 の表 → 06 の凸包）から補間関数を外すだけ。B 系ではないが補間なし。
MLIP で B 系を回す順序：(1) 共存 MD で融点・液相線（GPU、ACE / GRACE-FS）。(2) 固溶限は fix atom/swap を GPU で試行数を減らして回すか、短距離秩序が本質の系では CE+MC。固溶限の温度依存に振動が効く系（Ag–Cu 型）では MD 込みの fix atom/swap が必要で、CE+MC では出ない。最初の一歩は Al–Li の ACE で fix atom/swap + pace/kk を 1 点（800 K、Δμ 1 つ）流して所要時間を測ること。

3. float32 と float64（2026-10-24 測定、env/lammps-gpu-grace/test/prec/）

MACE・SevenNet の既定 float32 が TI の精度（1 meV/atom）に足りるかを測った。結論：足りる。float32 の丸めは 1 評価あたり 0.1〜0.2 µeV/atom で、TI の統計誤差（0.1〜1 meV/atom）より 3 桁小さい。

SevenNet の有限差分（h = 0.01 Å）の力誤差 2.5 meV/Å は、1 評価あたりのエネルギー丸め 0.05 meV（256 原子の総和）/0.02 Å に相当し、解析力の誤差ではない。SevenNet の float64 実行は sevenn 0.12 の checkpoint 互換パッチと fx 定数が float32 固定で失敗した。GRACE の fp32 版は径方向 MLP だけを cuBLAS fp32 にする設計で、総和は倍精度。

運用（2026-10-25、ユーザー決定）：MLIP 比較は全工程を単精度で行う（GRACE nL は QHA も calphy も grace/<n>l/kk/fp32、MACE は QHA も default_dtype float32、SevenNet は元から float32）。fp64 しか無いのは ACE（pace）と GRACE-FS（grace/fs/kk）。結論：calphy の TI（サーモスタット付き）では float32 で問題ない。float64 が要るのは長い NVE と、エネルギー差 1e-5 eV 級を直接使う構造最適化・フォノン有限差分（03A の変位 0.01 Å では SevenNet の有限差分力誤差 2.5 meV/Å が効くので float64 か変位 0.03 Å 以上）。

5. libtorch 系 MLIP を calphy で回すときの注意（2026-10-24、SevenNet で実際に起きた）

pair_style hybrid/scaled の中でビリアルが消える。LAMMPS はサブスタイルに F·r 方式のフラグ（VIRIAL_FDOTR）を渡さない。サブスタイルが自前のビリアルを no_virial_fdotr_compute = 1 で宣言していないと（SevenNet 0.13 の pair_e3gnn がそう）、if (vflag) の分岐が飛んで圧力がゼロになり、calphy の NPT（液相の平衡化・reversible scaling）で箱が 12.9 → 91.6 Å に膨張し、エネルギーが −10²² eV に発散する。単独の pair_style e3gnn では圧力が正しいので plain の MD では気づかない。修正：両コンストラクタに no_virial_fdotr_compute = 1; を入れる（env/lammps-torch/build_sevenn.sh が自動適用）。修正後は hybrid/scaled 下の軌道が plain と一致し、λ = 1.222 の圧力が plain の 1.222 倍になる。pair_mace は元から宣言済み。
  • 検査の手順（新しい pair style を calphy に載せる前に必ず）：同じ構造で (1) plain、(2) hybrid/scaled v_lam <style>（λ = 1）、(3) λ = 1.222 の run 0 の圧力を比べる（env/lammps-torch/test/in.seq2、in.npt）。(2) が (1) と一致し、(3) が 1.222 倍なら可。NPT 200〜500 ステップで体積が plain と同じ推移をすることも見る。
  • pair_style mace は atom_modify map yes と newton on が要る（無いと segfault）。calphy には md.init_commands で渡す（run_aiida.py の calphy_block_extra）。
  • SevenNet は OpenEquivariance 無しだと 1 s/step（256 原子）で calphy に使えない。sevenn patch_lammps --oeq でビルドし、モデルも get_model -oeq で展開する（16 倍速：MF-ompa 0.064 s/step、SevenNet-0 0.03 s/step）。MACE-MPA-0 は float32 で 0.27 s/step（float64 の 4.7 倍速、エネルギー差 1e-5 eV/セル）。
  • QHA 側（ASE calculator）と calphy 側（LAMMPS pair style）は同じ重みの別実装なので、1 セルでエネルギーを突き合わせる：SevenNet-0 −835.881592（ASE）/ −835.88159180（LAMMPS）、MACE-MPA-0 float64 −831.078825 / float32 −831.07881959、GRACE-2L −830.201231（LAMMPSlib）/ −830.20123104（lmp_gpugrace）eV、256 原子。工程 01 の緩和も QHA と同じ計算器で行う（torch 系は同じ env のサブプロセス）。
  • 環境：MACE（e3nn 0.4.4 固定）と SevenNet 0.13（e3nn 0.6）は同居できないので env/mace と env/torch に分ける。libtorch の cmake は従来型の CUDA 配置を要求する（conda の targets/x86_64-linux/include を include/ にリンク）。
